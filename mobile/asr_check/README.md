# asr_check — проверка слуха storyfx на телефоне

Тестовое Android-приложение по D-018 / D-020: слух продукта — системный распознаватель телефона в режиме «на устройстве». Приложение измеряет то, что нужно решить до Flutter-версии:

1. **Доступен ли on-device режим** (`SpeechRecognizer.isOnDeviceRecognitionAvailable`) и какие языки заявляет on-device движок (кнопка «Русский на устройстве?» → `supportedOnDeviceLanguages`, Android 13+). **Важно (прогон 2026-11-26 на Xiaomi):** скачанный офлайн-пакет голосового ввода («Google Голосовой ввод → Распознавание офлайн»: русский 88 МБ скачан) и этот список — не одно и то же: пакет есть, а ru-RU в `supportedOnDeviceLanguages` нет. Поэтому единственная честная проверка «на устройстве ли распознавание» (D-001) — прогон **в авиарежиме**.
2. **Непрерывность**: распознаватель останавливается на паузах — приложение перезапускает его и считает перезапуски. На стыках могут теряться слова, на части телефонов при перезапуске звучит сигнал — слушать и смотреть журнал.
3. **Задержки** (для D-011, звук ≤ 1 с): начало речи → первый частичный результат; конец речи → итоговая фраза.
4. **Точность**: читаете вслух выбранную сказку (`assets/stories/`, сейчас Колобок и Рыбак — те же, что в прототипе) — по «Стоп» считается WER против эталона и частые путаницы.

Весь сеанс пишется в журнал на экране; «Экспорт» сохраняет журнал в Загрузки (`asr_check_*.log`) — файл прислать агенту на разбор.

## Сборка

```
gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Окружение на этой машине (2026-11-26): SDK — `C:\Android\Sdk` (закреплён в `local.properties`, в git не попадает; если проверка окружения не находит SDK сама — не страшно, сборка берёт путь отсюда; для скриптов сборки задавать `ANDROID_HOME='C:\Android\Sdk'`); JDK — изолированный Temurin 21 в `~/.android-app-building/toolchain/jdk-21` (ставит скрипт проверки окружения Kimi; дублировавшаяся копия SDK оттуда удалена). Две грабли, не наступать повторно: (1) у JBR Android Studio (21.0.10, тоже подходит по версии) в этом окружении Gradle-демон стартует и молча гаснет за ~0,25 с — клиент ждёт его по таймауту (на машине Kaspersky; лечение не искали — есть рабочий JDK); (2) git bash искажает кавычки путей с пробелами при вызове cmd — `C:\Program Files\...` в таких вызовах «не существует», PowerShell видит нормально.

## Замечания

- Зависимостей, кроме Kotlin, нет: чистый platform API, разрешение — только микрофон.
- Минимальный Android — 8.0 (API 26); on-device распознавание требует Android 12+ (API 31), проверка языкового пакета — Android 13+ (API 33). На телефоне без сервисов Google поведение и есть предмет проверки.
- `EXTRA_SPEECH_INPUT_*` (длина пауз и т.п.) — подсказки; системный распознаватель может их игнорировать, это часть эксперимента.
