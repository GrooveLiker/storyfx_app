# StoryFX — живая озвучка рассказа

## Жёсткие правила (читать первыми)

1. **Всё работает локально.** Никаких облачных ИИ/STT во время работы приложения. Облако допустимо только как инструмент разработчика (например, сгенерировать обучающие примеры). См. [DECISIONS.md](DECISIONS.md) D-001.
2. **Голос не сохраняется.** Аудио с микрофона не пишется на диск и никуда не отправляется. Исключение — тестовые WAV, синтезированные TTS.
3. **Готово = проверено.** Задача считается сделанной только после прохождения команд из раздела «Проверка». «Код написан» ≠ «готово».
4. **WIP = 1.** Одна активная задача из [PROGRESS.md](PROGRESS.md). Не расширять объём без записи в PROGRESS.md.
5. **Звуки — только с понятной лицензией** (CC0 / свои / синтезированные). Внешние — через `tools/fetch_freesound.py` (проверяет CC0) + `tools/pick_sounds.py` или каталог `tools/catalog.py` (пишут `sounds/chosen.yaml` и `LICENSES.md`; свои записи — в `sounds/own/`). Ключ API — только в `prototype/.freesound_key`, не в коде и не в git.
6. **Данные отдельно от кода.** Триггеры и сцены — в `prototype/data/*.yaml`, не хардкодить слова в Python.
7. **Обновлять документы в том же изменении**, что меняет поведение (CLAUDE.md, PROGRESS.md, docs/).
8. Платформа разработки — Windows 10, PowerShell. Python 3.11, виртуальное окружение `prototype/.venv`.

## Что это

Приложение слушает рассказчика (ведущий ДнД или родитель, читающий сказку) и в реальном времени включает:
- **фон** — зацикленные звуки окружения (лес, дождь, таверна…), плавно сменяются;
- **персонажей** — голос при первом появлении (медведь — рык, старик — кряхтение), см. docs/characters.md;
- **действия** — короткие звуки на события (удар меча, падение, заклинание), задержка ≤ 1 с от конца слова (D-011);
- **музыку** (можно выключить) — синтетические петли по настроению рассказа: спокойная, весёлая, тревожная, динамичная.

Целевой продукт — мобильное приложение (Flutter, позже). Сейчас — **прототип на ПК (Python)** для проверки идеи.

## Структура

```
CLAUDE.md          — этот файл (маршрутизация)
PROGRESS.md        — текущее состояние, задачи, следующий шаг
DECISIONS.md       — журнал решений (почему так, что отвергли)
docs/architecture.md — устройство конвейера
docs/sounds.md     — как добавлять звуки, действия (по смыслу) и сцены
docs/fairytales.md — 100 сказок → места → какие фоны нужны (откуда список сцен)
docs/characters.md — персонажи этих сказок → звук появления
prototype/
  init.ps1         — установка окружения с нуля + быстрая проверка
  verify.ps1       — полная проверка (3 уровня)
  requirements.txt — зависимости с версиями
  src/storyfx/     — код: три звена (D-011) — asr (слух) → наблюдатели actions/scenes/characters/mood → world (модель мира) → engine+mixer+audio (звукорежиссёр)
  data/            — actions.yaml (действия по смыслу), scenes.yaml, characters.yaml (персонажи → голос), moods.yaml (настроение → музыка), muted.yaml (выключенные звуки)
  sounds/          — ambience/*.wav, sfx/*.wav (не в git), chosen.yaml (выбор), LICENSES.md, own/ (свои записи, в git)
  models/          — модель Vosk (скачивается init.ps1, не в git)
  tools/           — story_run.py (прогон сказки через движок → отчёт), catalog.py + live_session.py (каталог звуков и тест озвучки в браузере), gen_sounds.py (заглушки), gen_music.py (музыка), fetch_freesound.py + pick_sounds.py (настоящие звуки), make_test_wavs.py (TTS)
  tests/           — pytest
```

## Запуск (из папки `prototype`)

```powershell
./init.ps1                                   # один раз: venv, модели, звуки, быстрые тесты
./.venv/Scripts/python -m storyfx             # слушать микрофон
./.venv/Scripts/python -m storyfx --text      # печатать текст вместо речи («!музыка» — вкл/выкл)
./.venv/Scripts/python -m storyfx --wav tests/wav/forest_dnd.wav --no-audio --fast  # прогнать WAV
```

Режимов нет: звукооператор сам подстраивает микс под рассказ — по смыслу и темпу речи (D-010).

Из любой папки (корневой запускатель, те же аргументы): `D:\storyfx_app\run.cmd`

Каталог звуков и тест озвучки (послушать, выбрать, оставить; текст или диктовка → звук): `D:\storyfx_app\run_catalog.cmd` → http://127.0.0.1:8765

Совет: при работе с микрофоном используйте наушники — иначе микрофон слышит звуки приложения.

## Проверка

```powershell
./verify.ps1
```

Уровни (по порядку, нельзя пропускать):
1. **Статика** — `python -m compileall src` и загрузка YAML-данных.
2. **Поведение** — `pytest -m "not slow"`: логика действий (части фразы, ожидание контекста, отрицания, кулдаун), сцены, движок с фейковым аудио.
3. **Сквозная** — `pytest -m slow`: TTS-WAV → Vosk → ожидаемые события; выбор звука по смыслу на новых фразах (порог 85%); угадывание сцен; **сказки целиком** (`tests/test_stories.py`: что обязано / не должно прозвучать, `tests/story_expectations.yaml`; известные ошибки — `known_failing`, исправил → убрать из списка).

Ручная проверка (её агент сделать не может): живой микрофон, оценка на слух — записывать результаты в PROGRESS.md.
