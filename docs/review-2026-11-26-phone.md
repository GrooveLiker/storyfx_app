# Первый прогон слуха на телефоне 2026-11-26 — разбор

Источник: `docs/phone-2026-11-26.log` — приложение `asr_check` v0.1 на Xiaomi 2412DPC0AG, Android 16 (API 36). Владелец рассказывал импровизацию (та же история про племя невров, что в живом тесте ПК `review-2026-11-26.md`), свободный режим без эталона, ~2,5 минуты, 16 фраз.

## По четырём рискам D-018

1. **On-device режим работает.** `isOnDeviceRecognitionAvailable` = да, движок — `createOnDeviceSpeechRecognizer`. Русский пакет не проверен (в v0.1 кнопка требовала «Старт» — исправлено в v0.2).
2. **Нет времени слов** — подтверждено: приходят только текстовые результаты и события «речь началась/кончилась». Резку фраз по паузам (D-014) на телефоне делать по этим событиям — они приходят сами на каждой паузе.
3. **Задержка — отличная.** Итоговая фраза через 15–90 мс после «речь кончилась». Для D-011 (звук ≤ 1 с) запас огромный. (Медианы в журнал v0.1 не писались — экран только; v0.2 пишет итог в файл.)
4. **Перезапуски — частые, стыки теряют слова.** 13 перезапусков за 2,5 мин: распознаватель завершает сессию на каждой паузе, подсказки `EXTRA_SPEECH_INPUT_*` игнорирует. Наблюдаемые потери на стыках: «землянках» без начала фразы, «имрак» вместо «…Олег, Таргитай и Мрак», одна фраза (8,3 с речи) потеряна целиком — NO_MATCH. Сигналы при перезапуске — спросить владельца (в журнале не видно).

## Качество распознавания

Заметно лучше маленького Vosk на той же истории (ср. `review-2026-11-26.md`: «в нем же учебник», «на хиро машине»). Тут почти чисто: «Олег собирал травы он был волхвом таргетай был музыкантом он играл на дудочке а мрак было охотником он стрелял из лука добывал зверей». Плывут имена (таргетай/трагетай) и отдельные слова («был свидетехневров», «гриль семьи землянки»). Честный WER — следующим прогоном: читать «Колобка» или «Рыбака» из списка в приложении (там эталон, по «Стоп» посчитается WER).

## Прочее из журнала

- Xiaomi шлёт `onEndOfSpeech` дважды на каждую фразу — в v0.2 дедупликация.
- После «Стоп» приходили события последней сессии — в v0.2 не логируются.
- Раз в ~11 с новая сессия слушания; «готов к речи» через ~0,3 с после «слушаю…» — пауза глухого окна короткая.

## Вывод для storyfx

Слух телефона пригоден и лучше ПК-стенда: on-device, быстро, точно. Единственная системная проблема — стыки фраз (потерянные слова, редкий NO_MATCH). Движок к пропускам частично устойчив (якоря + смысл), но на телефоне стоит: (1) события «конец речи» использовать как естественную резку фраз; (2) фразы-обрывки из 1 слова («землянках», «имрак») склеивать с предыдущей — как перенос хвоста D-015.

## Вторая сессия 12:08–12:12 (`docs/phone-2026-11-26-kolobok.log`): чтение «Рыбака» по эталону

- **Офлайн-пакет русского СКАЧАН** (скриншот настроек «Google Голосовой ввод → Распознавание речи офлайн» от владельца 2026-11-26: «Русский (Россия), 88 МБ, v3059» и English (US)). Однако `supportedOnDeviceLanguages` системного API — 31 язык, и **ru-RU среди них нет** (en-US, de-DE, es-ES, fr-FR, it-IT, ja-JP, ko-KR, pt-BR, cmn-Hans-CN…). Значит, скачанный пакет голосового ввода и список языков on-device `SpeechRecognizer` — не одно и то же: пакет есть, а системный движок «на устройстве» про русский не отчитывается. Следствие на тот момент: **офлайновость обоих прогонов не доказана** — журнал этого не показывает. Решающая проверка — прогон в авиарежиме → **сделан в третьей сессии (см. ниже): D-001 подтверждён, офлайн русский работает**.
- **Шторм перезапусков — баг harness v0.2, не телефона**: 626 перезапусков и 570 ошибок CLIENT за 3,5 мин. Цепочка: кнопка поддержки создала распознаватель → «Старт» пересоздал → разрыв сервиса (SERVER_DISCONNECTED) → гонка отложенных таймеров перезапуска → параллельные `startListening` → CLIENT по кругу. Живая сессия при этом работала и выдавала фразы.
- **WER 79,7% — нечестный из-за шторма**: 675 из 943 слов эталона — пропуски (куски текста не попали в распознанное), замен всего 73, лишних 4. Путаницы в основном артефакты формы: «тридцать»→«30», «своею»→«своей», «корыто»→«корыта». Честный WER — на v0.3.
- Задержки: речь→первый частичный медиана 1258 мс (ждёт накопления речи), конец речи→фраза 0 мс (макс 11 мс) — итоговая фраза мгновенно после конца речи.
- **v0.3 (2026-11-26):** один таймер перезапуска (removeCallbacks перед postDelayed), отмена отложенного перезапуска на «готов к речи»/«речь началась», BUSY/CLIENT на живой сессии не перезапускают, backoff 1000 мс на BUSY/CLIENT/SERVER_DISCONNECTED/TOO_MANY_REQUESTS, распознаватель создаётся один раз (`ensureRecognizer`), WER разворачивает цифры в слова («30»→«тридцать»).

## Третья сессия 13:12 (`docs/phone-2026-11-26-airplane.log`): АВИАРЕЖИМ — проверка D-001

- **D-001 ПОДТВЕРЖДЁН**: в авиарежиме распознавание работает — on-device движок распознал русскую речь без сети (2 фразы, сессия слушания 24 с подряд). Загадка «пакет скачан, а `supportedOnDeviceLanguages` без ru-RU» решена практически: список API не отражает реальные возможности движка на этом Xiaomi — офлайн русский работает, чего бы API ни сообщал.
- **Непрерывность стала лучше**: одна сессия слушания длилась 24,3 с речи без перезапуска (в v0.1 был потолок ~11 с). Итого 2 перезапуска на 2 фразы, NO_MATCH 0. Задержки: речь→первый частичный 1892 мс, конец речи→фраза 7 мс.
- **Но качество слов — плохое**: читалось начало «Колобка», услышано 87 слов, из них замен 40 (~46%). Плывут именно редкие/архаичные слова: «по сусеку»→«после» ×2, «авось»→«памяти», «пригоршни»→«приглашенами», «постудить»→«кошка пасту», «окошко»→«кошка», «поскреби» потерян; местами бессвязный набор («соскочил с окошка…» → «прижата вдруг я пока делается высоко»). WER 89,4% в журнале не о качестве: эталон — весь «Колобок» (407 слов), а прочитано только начало (322 пропуска — непрочитанный текст).
- **Две гипотезы качества** — различает один чистый эксперимент: (а) on-device модель слабее того, что давало хороший текст в прошлых прогонах (тогда те прогоны шли через сервер, и их «отличное качество» — не заслуга on-device); (б) условия чтения этого прогона (скорость, дикция, расстояние до микрофона). Эксперимент: прочитать **«Рыбака» в авиарежиме** — есть онлайн-прогон «Рыбака» для прямого сравнения замен на прочитанной части.
- Продуктовое следствие, если подтвердится (а): слух продукта офлайн, но уровень ошибок сопоставим с маленьким Vosk — тогда вопрос D-020 «телефон против Vosk» открывается заново, и имеет смысл замерить на телефоне оба (системный on-device против Vosk в приложении) на одном тексте.
