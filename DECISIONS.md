# Журнал решений

Формат: дата · решение · почему · что отвергли.

## D-001 · 2026-11-05 · Только локальные модели
**Решение:** распознавание речи и анализ сцены выполняются на устройстве.
**Почему:** работа без интернета, нулевая стоимость использования, приватность (голос детей), стабильная задержка.
**Отвергли:** облачные LLM (Claude/GPT) для определения сцены и облачный STT (Yandex SpeechKit, Deepgram) — стоимость, зависимость от сети, приватность.

## D-002 · 2026-11-05 · Два слоя распознавания смысла
**Решение:** (1) быстрый слой — ключевые слова по основам слов (Snowball-стеммер) → звуки действий за миллисекунды; (2) медленный слой — классификатор сцены по смыслу раз в несколько секунд → фон.
**Почему:** действиям нужна задержка < 0,5 с, а сцене достаточно нескольких секунд; смысловая модель слишком медленна и неточна для мгновенных событий.
**Отвергли:** одна LLM на всё — медленно и тяжело для телефона.

## D-003 · 2026-11-05 · Классификатор сцены — rubert-tiny2 + сравнение с описаниями
**Решение:** модель `cointegrated/rubert-tiny2` (~30 МБ) считает векторы смысла; сцена = ближайшая к описаниям из `scenes.yaml`, плюс бонус за ключевые слова сцены, плюс гистерезис (сцена должна выиграть дважды подряд).
**Почему:** маленькая, быстрая, хорошо знает русский, не требует обучения на старте. Переносится на телефон через ONNX/TFLite.
**Отвергли пока:** локальные LLM 1–3B (Qwen, Gemma) — 1–2 ГБ, секунды на запрос, батарея. Вернуться как к «умному режиму» для мощных телефонов. Дообучение классификатора — следующий шаг, если точности не хватит.

## D-004 · 2026-11-05 · Прототип на Python для ПК
**Решение:** сначала проверить идею на ПК: Vosk (`vosk-model-small-ru-0.22`) + pygame.mixer + sentence-transformers.
**Почему:** быстрая итерация; те же модели (Vosk, rubert-tiny2) потом работают на телефоне.
**Отвергли:** сразу Flutter — дольше, а главные риски (задержка, ложные срабатывания, «вау-эффект») не зависят от платформы.

## D-005 · 2026-11-05 · Звуки-заглушки синтезируются кодом
**Решение:** `tools/gen_sounds.py` генерирует все звуки из шума и синусоид (numpy/scipy).
**Почему:** нет проблем с лицензиями и скачиванием; прототип работает «из коробки». Реальные звуки (Freesound CC0 и т.п.) кладутся поверх с теми же именами файлов.
**Отвергли:** скачивание с Freesound — нужен API-ключ и проверка лицензии каждого файла.

## D-007 · 2026-11-05 · Звуки действий по смыслу фразы, а не по слову
**Решение:** `actions.yaml`: тема = слова-якоря + варианты с примерами фраз + `_none`. Часть фразы с якорем классифицируется логистической регрессией поверх векторов rubert-tiny2 (обучение на примерах при запуске). Заменяет D-002 (слой 1) и `triggers.yaml`.
**Почему:** отзыв владельца после теста с микрофоном: «лошадь прискакала» → скач, «погладил лошадь» → фырканье. Владелец подтвердил, что задержку можно увеличить — ждём 4 слова после якоря или конца фразы.
**Сравнение (12 контрольных фраз про лошадь, классы скач/фырканье/без звука):**
| Модель | ближайший пример | классификатор | скорость |
|---|---|---|---|
| rubert-tiny2 | 11/12, отрыв 0,05 | **12/12, уверенность 0,77** | 3 мс |
| rubert-tiny-turbo | 12/12, отрыв 0,03 | 10/12, 0,68 | 3 мс |
| multilingual-e5-small | 6/12 | 11/12, 0,58 | 13 мс |
Удаление слова-темы из фразы перед сравнением не помогло (6/8 против 7/8).
**Отвергли:** голое сравнение с примерами (слишком малый отрыв — «монетка»), модели крупнее (хуже и медленнее), локальную LLM (D-003).
**Ограничение:** якоря всё ещё нужны — без них классификатор вызывался бы на каждой фразе и давал бы ложные срабатывания.

## D-006 · 2026-11-05 · Сквозные тесты через Windows TTS
**Решение:** тестовые WAV синтезируются голосом Microsoft Irina (System.Speech) и прогоняются через Vosk.
**Почему:** агент не может говорить в микрофон; так проверяется весь конвейер речь → текст → события.
**Ограничение:** синтетическая речь чище живой; живой микрофон проверяется вручную.
